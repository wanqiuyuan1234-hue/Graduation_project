# CodeRAG 前端项目分析报告

> 项目名称：**CodeRAG · 代码仓库 RAG 问答系统**
> 项目路径：`c:\no_space_demand\Graduation-project-front`
> 定位：一个**纯前端展示项目**（FastGPT 风格复刻），目前**完全没有对接真实后端**，所有业务数据均为本地 Mock（假数据），仅依赖浏览器 localStorage 做本地持久化。

---

## 一、前端采用的语言与框架

| 类别 | 技术选型 | 说明 |
| --- | --- | --- |
| **核心框架** | Next.js 16（App Router 模式） | React 全栈框架，支持 SSR / RSC / API 路由 |
| **UI 库** | React 19 | 组件化 UI 开发 |
| **开发语言** | TypeScript | 强类型（需注意：`next.config.ts` 中 `typescript.ignoreBuildErrors: true`，即构建时忽略 TS 报错） |
| **样式方案** | Tailwind CSS 4 + shadcn/ui | Tailwind 原子化样式 + Radix UI 组件集 |
| **状态管理** | Zustand（含 persist 中间件） | 全局导航/会话/主题等状态，持久化到浏览器 localStorage |
| **动画** | framer-motion | 面板滑出、弹窗等过渡动画 |
| **图标** | lucide-react | 矢量图标 |
| **ORM（未实际使用）** | Prisma | `schema.prisma` 仅含演示用 User/Post 模型，业务未使用 |
| **认证（未实际使用）** | next-auth | 依赖存在，但业务未接入 |
| **i18n（未实际使用）** | next-intl | 依赖存在，未启用 |
| **LLM SDK** | z-ai-web-dev-sdk | 唯一可能对接真实 LLM 的通道（见 `/api/chat`） |
| **运行时** | Node.js / Bun | `package.json` 中 `start` 脚本使用 `bun` 运行 standalone 产物 |

**关键结论**：整个项目是基于 **Next.js 16（App Router）+ React 19 + TypeScript + Tailwind CSS 4 + shadcn/ui + Zustand + framer-motion** 的单体前端工程，业务逻辑集中在 `src/components/rag/**` 与 `src/lib/rag/**` 两个目录。

## 二、页面与功能全景

项目是**单页应用（SPA）**结构，通过 Zustand 中的 `view` 状态在 4 个主视图之间切换，另有多个弹窗/面板/对话框作为辅助界面。

### 2.1 四个主视图

| 视图 | 对应组件 | 入口 | 功能概述 |
| --- | --- | --- | --- |
| **模块浏览** | `module-browser.tsx` | `g` + `m` | 代码模块的卡片列表，支持筛选/搜索/排序 |
| **模块详情** | `module-detail.tsx` | 点击模块卡片 | 单个代码模块的完整信息（代码、元数据、调用链、切片边界） |
| **对话问答** | `chat-page.tsx` | `g` + `c` | 核心 RAG 问答界面，含流式回复、引用溯源、检索调试 |
| **知识库** | `knowledge-base.tsx` | `g` + `k` | 知识库管理（统计、仓库拉取、切片策略、文件树、切片预览） |

### 2.2 通用布局组件（所有视图共享）

- **侧边栏 `app-sidebar.tsx`**：主导航（模块浏览 / 对话问答 / 知识库）+ 仓库列表（含状态徽标）。
- **顶栏 `app-header.tsx`**：导航、主题切换、设置入口、命令面板（Cmd+K）入口、当前仓库信息。
- **页脚 `app-footer.tsx`**：返回顶部、快捷键入口。

### 2.3 模块浏览页（Modules）

- 仓库 / 语言 / 类型三重筛选。
- 关键词搜索（按名称、文件路径、摘要、标签）。
- 模块卡片排序。
- 模块卡片 `module-card.tsx`：类型徽标、语言徽标、复杂度环、标签、切片数。

### 2.4 模块详情页（Module Detail）

- 四个 Tab：**代码 / 元数据 / 调用链 / 切片边界**。
- 自研代码高亮查看器 `code-viewer.tsx`（手写分词器，支持 TS / JSX / Python / Go / Rust），行高亮、复制。
- 参数表、AST 路径、关联模块、引用记录。

### 2.5 对话问答页（Chat）——核心功能

- **消息操作**：发送 / 停止生成 / 继续 / 重新生成 / 编辑消息 / 清空 / 跳转代码 / 重新检索。
- **流式打字机效果**：`streamReply` + `SPEED_CONFIG` 控制打字速率（可在设置中调节）。
- **LLM 调用链**：`fetchReply` 调用 `/api/chat`，失败时回退到前端 Mock 的 `generateReply`。
- **会话侧边栏 `session-sidebar.tsx`**：新建 / 删除 / 重命名 / 搜索会话。
- **来源面板 `source-panel.tsx`**：右侧弹簧滑出的引用来源展示。
- **检索调试面板 `retrieval-debug.tsx`**：topK 滑块、重排（Rerank）开关、向量权重滑块、重新检索。
- **历史版本对比 `message-history.tsx`**：自实现 LCS 单词级 diff。
- **行内消息编辑 `message-editor.tsx`**。

### 2.6 知识库页（Knowledge Base）

- 统计卡片（仓库数、模块数、切片数等）。
- 仓库卡片、拉取仓库对话框。
- 切片策略选择（5 种：AST 切分等）。
- 文件树 `file-tree.tsx` + 切片预览。

### 2.7 弹窗 / 面板 / 对话框

- **设置对话框 `settings-dialog.tsx`**：主题 / 流式速率 / 数据管理 / 关于。
- **命令面板 `command-palette.tsx`**：Cmd+K（Ctrl+K）快速导航。
- **快捷键帮助 `shortcuts-dialog.tsx`**：`?` 触发。

### 2.8 键盘快捷键

| 快捷键 | 功能 |
| --- | --- |
| `g` + `m` | 跳转模块浏览 |
| `g` + `c` | 跳转对话问答 |
| `g` + `k` | 跳转知识库 |
| `/` | 聚焦搜索框 |
| `t` | 切换明暗主题 |
| `?` | 显示快捷键帮助 |
| `Esc` | 关闭来源面板 / 弹窗 |
| `Cmd/Ctrl + K` | 打开命令面板 |

## 三、数据流与持久化机制（现状）

### 3.1 Mock 数据来源

> **所有业务假数据统一集中在** `src/lib/rag/mock-data.ts` **一个文件中**。

| 数据项 | 变量名 | 内容 |
| --- | --- | --- |
| 仓库列表 | `REPOS` | 3 个仓库（fastgpt-sdk / next-chat / vector-store） |
| 切片策略 | `SLICE_STRATEGIES` | 5 种切分策略 |
| 代码模块 | `MODULES` | 12 个模块（含完整代码片段） |
| 源码切片 | `SOURCE_CHUNKS` | 5 个切片 |
| 聊天会话 | `CHAT_SESSIONS` | 4 个带完整问答的会话 |
| 文件树 | `FILE_TREES_BY_REPO` | 每个仓库的文件树 |
| 建议问题 | `CHAT_SUGGESTIONS` | 问候建议 |

辅助查询函数：`getModulesByRepo` / `getModuleById` / `getRepoById` / `getFileTreeByRepo`。

### 3.2 持久化机制

- 导航/会话/主题等**交互状态**通过 Zustand `persist` 中间件持久化到浏览器 **localStorage**（键名 `coderag-nav`、`coderag-theme`）。
- 会话消息经过 `slimMessage` / `fattenMessage` 做瘦身/恢复。
- **重要**：这意味着会话数据仅存在于用户本地浏览器，刷新不掉，但**换浏览器/清缓存后即丢失**，无法跨设备同步。

### 3.3 API 路由现状

| 路由 | 状态 | 说明 |
| --- | --- | --- |
| `/api` | 演示 | 返回 `{ message: "Hello, world!" }` |
| `/api/chat` | **可选对接真实 LLM** | 使用 `z-ai-web-dev-sdk`，配置 env 后可调真实 LLM；否则抛错，前端回退 Mock |
| `/api/retrieve` | **纯 Mock** | 从 `SOURCE_CHUNKS` 采样并伪随机打分，未接真实向量库 |

## 四、需要对接后端的数据清单

> 以下数据目前全部是前端硬编码 Mock 或本地 localStorage，需替换为真实后端接口。

| 消息 | localStorage | 持久化到数据库，支持跨设备同步 |
| 用户身份 | 无（next-auth 未接入） | 接入认证，会话按用户隔离 |

### 4.4 知识库管理动作（需后端触发）

| 动作 | 现状 | 对接建议 |
| --- | --- | --- |
| **拉取仓库** | 前端对话框，无真实拉取 | 后端 Git 克隆/同步接口 + 同步状态轮询 |

- 需提供真实后端「数据库连接串 + LLM/Embedding/Rerank 服务地址 + 对象存储（如需）」。

## 五、推荐的运行软件与启动方式

### 5.1 必需软件

| 软件 | 用途 | 版本建议 |
| --- | --- | --- |
| **Node.js** | JavaScript/TypeScript 运行时 | LTS（20+ 或 22+） |
| **Bun**（可选但推荐） | 包管理 + 运行时，`start` 脚本使用 | 最新稳定版 |
| **VS Code** | 代码编辑器 | 任意最新版 |

> 项目 `package.json` 的生产 `start` 脚本使用 `bun .next/standalone/server.js`，因此**部署/生产运行强烈建议安装 Bun**；纯开发（`next dev`）用 Node.js 即可。

### 5.2 依赖安装

项目使用 Next.js 16，若本地无 `package-lock.json` / `bun.lock`，任选其一安装依赖：

```bash
# 方式一：npm
npm install

# 方式二：bun（更快，推荐）
bun install
```

### 5.3 启动开发服务器

```bash
# npm
npm run dev          # 等价于 next dev -p 3000

# 或 bun
bun run dev
```

启动后浏览器访问：**http://localhost:3000**

### 5.4 生产构建与启动（可选）

```bash
# 构建（standalone 产物）
npm run build        # 或 bun run build

# 生产启动（使用 Bun 运行 standalone）
npm start            # 等价于 NODE_ENV=production bun .next/standalone/server.js
```

### 5.5 反向代理（可选）

项目自带 `Caddyfile`，可用 Caddy 在 `:81` 端口做反向代理转发到 `localhost:3000`（适合部署场景，可选）。

## 六、总结

1. **技术栈**：Next.js 16（App Router）+ React 19 + TypeScript + Tailwind CSS 4 + shadcn/ui + Zustand + framer-motion，八说明性依赖（Prisma / next-auth / next-intl）暂未实际使用。
2. **页面**：单页应用，内含 4 个主视图（模块浏览 / 模块详情 / 对话问答 / 知识库）+ 多个弹窗面板，功能完整度较高。
3. **现状本质**：**纯前端 + Mock 数据**。所有业务数据硬编码在 `src/lib/rag/mock-data.ts`，会话数据仅存 localStorage。
4. **待对接后端**：仓库/模块/切片 CRUD、向量检索 + Embedding、重排、LLM 生成、会话持久化 + 账号、仓库拉取与切片入库。
5. **运行**：安装 Node.js（建议加装 Bun）→ `npm install`（或 `bun install`）→ `npm run dev` → 访问 `http://localhost:3000`。
